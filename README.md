# Live2Dマスコット連携わんコメプラグイン

わんコメの新着コメントをWebSocketで [Live2D Desktop Mascot](https://github.com/fixtan/live2d-desktop-mascot) へ送り、マスコットに読み上げてもらう補助プラグインです。連携先のマスコットアプリを別途インストールし、起動して使用してください。

## 試し方

1. マスコットを起動し、わんコメでプラグインを有効にする。
2. 接続済みになったら「テスト送信」で短いテスト文を送る。
3. 「コメントをマスコットへ送信する」にチェックする（自動保存）。

初期状態ではコメント送信は無効です。設定は配置フォルダのsettings.jsonに保存します。自分のコメントを除外する場合は、自分のユーザーIDを指定してください。自己コメントフラグ（data.isSelf/isMe）も判定します。配信者を示す場合があるisOwnerは判定に使用しません。

## コメントの選択と送信

プラグイン有効化後の最初の空でない受信配列は全件を読み上げず、重複除外のために記録します。空配列では初回扱いを消費しません。その後もdata.timestampがプラグイン起動時刻より古ければ除外します。時刻はUNIXミリ秒・UNIX秒（数値または数値文字列）・タイムゾーン付きISO日時に対応します。履歴に新しい値が付くreceivedAtは判定に使用しません。秒単位の時刻では起動と同じ秒の新着も除外される場合があります。

初回以降に時刻が欠けている・解釈できない場合は、重複除外と明示的な履歴フラグで判定します。時刻のない履歴が複数回に分かれ、まだ受信していないIDで届く場合は新着との区別ができません。最初の受信に新着が含まれる場合もその1回は読みません。

以降の新着コメントは受信配列の順序で全件をキューへ追加します。サービス・配信・コメントIDで30分間の重複除外を行います。IDがなければユーザーID・時刻・本文を使用し、IDと時刻の両方がなければ10秒間だけ重複を除外します（最大5000件）。送信無効中も記録し、有効化時に過去分を読みません。

キュー設定は画面から保存できます。

- 送信待ち上限: 1〜100件、初期値20件（送信中の1件は含まない）
- 待機期限: 1〜3600秒、初期値60秒
- 上限時の処理: 待機中の最も古いコメントを落とす（初期値）、または新しいコメントを落とす
- 送信間隔: 1000〜60000ミリ秒、初期値5000ミリ秒

期限切れのコメントは送信しません。送信無効化・接続先変更・手動再接続・終了時は待機を破棄します。通常の設定変更では待機を保持し、上限を減らした場合は選んだ破棄方針で超過分を落とします。すでに送信した音声を中断する機能はありません。手動テストも同じキュー設定に従います。起動時の除外件数と、キュー破棄・期限切れの件数を画面で確認できます。

本文はdata.speechTextを優先し、なければdata.commentのHTMLを除去します。テンプレートの{name}はわんコメのnickname、アカウント表示名のname、screenNameの順で選びます。{nickname}はわんコメ名のみ、{accountName}はアカウント表示名のみ、{screenName}は受信スクリーン名のみ、{comment}は本文です。個別の名前項目が欠けていれば空文字となり、別の名前で補いません。画面の「読み上げる名前」で、自動選択・わんコメ名のみ・アカウント名のみ・スクリーン名のみを選べます。文字数上限は200文字までです。sayには発声完了の応答がないため、送信間隔は発声完了を保証しません。sentCountはWebSocket送信件数です。送信失敗時は重複を避けるため自動再送しません。

## 接続とファイル選択

通常は %APPDATA%\Live2D Desktop Mascot\bridge.json を自動検出します。「参照…」はWindows標準のファイル選択ダイアログを開きます。選択したパスは自動保存されます。キャンセル時は変更しません。Windows以外ではパスを直接入力してください。

環境変数MASCOT_BRIDGE_FILEでも既定パスを指定できます。接続先は127.0.0.1に限定し、トークンは画面・ログ・設定ファイルへ返しません。welcome受信後に接続完了とし、切断後は3秒ごとにbridge.jsonを読み直して再接続します。接続・welcome待機は5秒でタイムアウトします。

## 開発

Bun 1.3以上を使用します。

```sh
bun install
bun run typecheck
bun test
bun run build
bun run dev
```

ビルド結果はdist/live2d-mascot-onecomme-plugin/です。plugin.jsとindex.htmlを %APPDATA%\onecomme\plugins\live2d-mascot-onecomme-plugin\ へコピーしてください。既存のsettings.jsonは保持してください。wsはビルドに同梱され、配置先にnode_modulesは不要です。

参照元・接続仕様は [docs/development.md](docs/development.md) を参照してください。

名前がすべてない場合の最後のフォールバックは、設定した呼び名（初期値「視聴者」）か「名前を呼ばず本文だけ読む」を選べます。

通常のテンプレートは{name}{honorific}、{comment}です。{honorific}は敬称欄の内容（初期値「さん」）で、空欄にもできます。区切りの「、」はテンプレート内で自由に変更します。名前が空の場合は、名前の直後の{honorific}と、それに続く句読点・空白をまとめて省略します。例えば{name}{honorific}、{comment}は、名前がある場合「花子さん、こんにちは」、名前を省略する場合「こんにちは」になります。カスタムテンプレートの他の文言は保持します。敬称をテンプレートへ直接書くと省略の対象にできないので、{honorific}を使用してください。

旧形式の単純な名前＋敬称＋本文テンプレートと{speaker}形式は、読み込み時に呼び方を保って新形式へ移行します。任意のカスタムテンプレートは自動変更しません。

設定は変更時に自動保存します。文字入力は約0.5秒まとめ、チェックや選択の変更はすぐ保存します。日本語変換中は確定まで入力保存を待ちます。保存中・自動保存済み・失敗を画面へ表示し、失敗時は入力を保ったまま再試行できます。保存済みの状態を確認してから画面を閉じてください。待機中のコメントは登録時の文章と待機期限を保持し、以降の新着へ新しい設定を適用します。

## GitHub Actionsでのビルド・リリース

参照元のthank-you-card-onecomme-pluginと同じく、vで始まるタグをpushするとBuild and Releaseが実行されます。Bun 1.3.11で依存関係を固定してインストールし、型チェック・テスト・ビルドが通った後にZIPをGitHub Releasesへ添付します。

タグはpackage.jsonとsrc/plugin.tsのバージョンに合わせてください（現在はv0.2.0）。両者のバージョンが一致しない場合やタグが異なる場合は、リリース前に停止します。

```sh
git tag v0.2.0
git push origin v0.2.0
```

GitHubのActions → Build and Release → Run workflowから手動で実行した場合は、ビルド済みZIPをActionsの成果物として保存します。手動実行ではReleaseを作りません。

配布ファイルはlive2d-mascot-onecomme-plugin.zipです。中のlive2d-mascot-onecomme-pluginフォルダをわんコメのpluginsフォルダへ配置してください。ZIPにはplugin.js、index.html、README.md、LICENSE、THIRD-PARTY-NOTICES.txtを含め、接続トークンや個人設定は含めません。
